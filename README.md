# 부러진 칼날 (Broken Blade)

검과 방패를 잃고 부러진 칼날 하나로 성문을 지키는 수문장이, 공격 대신 **패링과 회피만으로** 거대한 기사를 막아내는 1인용 보스전 액션 게임.

> 2026-2 임베디드소프트웨어 기말 프로젝트 · 1인 개발 · 2026.11.18 ~ 12.08

<br>

# 🎮 게임 소개

플레이어는 직접 공격할 수 없다. 보스의 공격을 정확한 타이밍에 패링하거나 피해야 하고, 패링에 성공해야만 보스에게 피해가 들어간다.

## 조작법

| 입력 | 동작 |
| --- | --- |
| 조이스틱 상하좌우 (대각선 포함 8방향) | 이동, 패링·회피 방향 지정 |
| A 버튼 (#5) | 회피 (짧은 구르기, 구르는 동안 무적) |
| B 버튼 (#6) | 패링 |
| 방향 + B | 방향 패링 (투사체를 그 방향으로 반사) |

조이스틱 가운데 누르기는 주변 4방향이 함께 입력되는 하드웨어 특성 때문에 사용하지 않는다.

## 보스 공격 패턴

보스는 공격 직전에 몸 주변이 특정 색으로 깜빡이고, 이 색으로 어떤 공격이 올지 알 수 있다.

| 패턴 | 예고 색 | 정답 대응 | 성공 시 |
| --- | --- | --- | --- |
| 일반 공격 | 흰색 | 패링 또는 회피 | 패링하면 보스에게 반격 피해 |
| 패링 불가 공격 | 빨간색 | 회피만 | 피해 없이 넘김 |
| 회피 불가 공격 (화면 전체) | 파란색 | 패링만 | 보스에게 반격 피해 |
| 부메랑 공격 | 노란색 | 날아올 때 회피, 돌아올 때 뒤쪽으로 방향 패링 | 보스에게 반사 피해 |
| 반사 패링 (투사체) | 초록색 | 구조물 쪽 또는 보스 쪽으로 방향 패링 | 구조물 쪽: 방패 기둥 파괴 / 보스 쪽: 반사 피해 |

## 진행

1. 타이틀 화면에서 아무 버튼이나 누르면 시작
2. **1페이즈**: 일반 공격, 패링 불가 공격
3. **2페이즈** (보스 체력 2/3 이하): 회피 불가·부메랑 공격 추가, 공격 속도 증가
4. **3페이즈** (보스 체력 1/3 이하): 보스가 방패 기둥 뒤에 숨어 투사체 발사, 반사로 기둥을 모두 부수면 다시 드러남
5. 보스 체력 0 → CLEAR / 플레이어 체력(5칸) 0 → GAME OVER 후 현재 페이즈부터 재시작

# 🛠 개발 환경

| 구분 | 사용 |
| --- | --- |
| 보드 | Raspberry Pi 4 |
| 화면 | 1.3" 240×240 TFT LCD (ST7789), SPI |
| 입력 | 5방향 조이스틱 + 버튼 2개, GPIO |
| 언어 | Python 3 |
| 라이브러리 | Adafruit Blinka, adafruit-circuitpython-rgb-display, Pillow, numpy |
| 미리보기 | pygame (맥에서 Pi 없이 실행) |
| 개발 도구 | VS Code Remote-SSH, Git·GitHub |

## 실행

```bash
cd ~/pi-game
source ~/env/bin/activate
python main.py
```
`Ctrl+C`로 종료하면 화면을 지우고 백라이트를 끈다.

# 📌 Convention

## 기본 원칙

- `main`에 직접 push하지 않는다. 모든 작업은 이슈 → 브랜치 → PR로 진행한다.
- 작업 시작 전 최신 `dev`를 pull한다.
- 이슈는 해당 작업을 시작할 때 하나씩 만든다.

## 🌿 Branch Strategy

```
main
dev        ← default
feature/*
fix/*
refactor/*
```

| 브랜치 | 설명 |
| --- | --- |
| `main` | 항상 실행되는 버전, 직접 push 금지 |
| `dev` | 개발 통합 브랜치, 작업 브랜치 병합 대상 |
| `feature/*` | 새 기능 |
| `fix/*` | 버그 수정 |
| `refactor/*` | 기능 변화 없는 코드 정리 |

```
feature/{영역}-{내용}
fix/{영역}-{내용}
refactor/{영역}-{내용}
```

예시: `feature/player-action`, `fix/parry-timing`

## 🔁 작업 순서

1. **이슈 생성**: Feature / Bug / Refactor 템플릿 중 하나로 작성, 마일스톤 지정
2. **브랜치 생성**: 최신 `dev`에서 작업 브랜치 생성
3. **커밋**: 작은 단위로, `type: 작업 내용` 형식
4. **PR**: `dev` ← 작업 브랜치, 제목은 `[타입] #이슈번호 제목`
5. **셀프 리뷰**: 체크리스트 확인 후 merge, 이슈 닫기
6. **주차 마무리**: 주차 마지막 날 `dev` → `main` 병합

## 💬 Commit Convention

```
type: 작업 내용
```

| 타입 | 쓰는 경우 |
| --- | --- |
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변화 없는 코드 정리 |
| `design` | 그림·화면 연출 변경 |
| `test` | 측정·테스트 코드 |
| `docs` | README·개발 일지 수정 |
| `chore` | 설정·패키지 등 기타 작업 |

예시: `feat: 패링 판정 구현`
